# 第二版 · 战术数据接入范围

**版本**：V2 范围说明  
**目标**：接入 StatsBomb 事件数据，使报告至少有一项战术指标来自真实事件。  
**与第一版关系**：在第一版报告与结构基础上，仅扩展「事件数据接入 + 少量真实指标」；伤停、政治、预测沿用第一版，不在此版大改。

---

## 一、数据源（已定）

| 项目 | 约定 |
|------|------|
| **供应商** | StatsBomb |
| **赛事** | 英超（English Premier League） |
| **赛季** | 2024/25 |
| **数据形态** | 文件（如每场 JSON / 批量导出），不在此版接 API 或多家数据源 |

---

## 二、成功标准

- **数据**：至少一场比赛能**稳定拉取** StatsBomb 事件数据（可本地文件读取，也可通过官方/第三方提供的文件包）。
- **报告**：赛前/赛后报告中，**至少有一项战术指标**来自这批事件数据；建议优先实现其一或两个：
  - 控球率（或控球时间占比），或
  - 射门次数 / xG（若 StatsBomb 数据带 xG 则直接使用）。
- **不要求**：多场批量、全赛季覆盖、所有战术指标、伤停/政治/预测模块的改造。

---

## 三、第二版不做啥

- **不接**多家数据源（仅 StatsBomb、仅英超 2024/25）。
- **不铺满**所有战术指标（阵型、压迫、转换、区域等可仍为占位或规则，后续版本再补）。
- **不顺便大改**伤停、政治四块、预测模块；沿用第一版逻辑与接口即可。

---

## 四、数据获取与文件形态（参考）

- **StatsBomb 开放数据**：可优先查看 [StatsBomb Open Data](https://statsbomb.com/news/statsbomb-release-free-data/)；开放数据覆盖赛事与赛季有限，若不含英超 2024/25，需通过商业/教育授权或第三方提供的文件获取。
- **文件形态**：常见为每场一个或多个 JSON（如 `events`、`lineups`、`matches`）；开发时需确认实际拿到的文件结构（目录、命名、字段名）。
- **本版约定**：以「本地文件读取」为主；若后续改为 API 或下载脚本，视为在同一「接入层」内扩展，不扩大第二版范围。

---

## 五、实现时需注意的点

| 要点 | 说明 |
|------|------|
| **比赛主键** | 统一用哪种 ID 标识一场比赛（如 StatsBomb 的 `match_id`，或 主队+客队+日期）。赛程、报告、事件数据都应对齐同一主键，便于后续多场扩展。 |
| **字段与口径** | 控球率：按「事件数」还是「持续时间」需在文档写死，避免同一指标多种算法。xG：若数据源带则直接用；否则第二版可只做射门次数。 |
| **主客队对应** | StatsBomb 通常用 `team.id` / `team.name`（英文）；报告侧为主客队中文名。需在接入层或配置中做一次映射（如 team_id/name → 主/客、中文队名），保证战术指标能正确归到「主队」「客队」。 |
| **与现有代码** | 第一版已有 `data/events.py`（load_events、normalize）、`tactics/metrics.py`（compute_metrics）。第二版在「读取 StatsBomb 文件 → 转为统一事件表」和「在 metrics 中算控球率/xG」两处扩展即可，尽量不改报告组装与政治/伤停接口。 |
| **配置** | 建议在 config 中增加「事件数据路径」「StatsBomb 文件格式/版本」等配置项，便于换文件路径或赛季时少改代码。 |

---

## 六、报告中的呈现

- **至少一项战术指标**来自事件：例如在「战术预期」或「战术复盘」中明确写出「控球率 主 XX% – 客 XX%」或「xG 主 X.X – 客 X.X」「射门 主 X – 客 X」。
- **无事件数据时**：保持第一版行为（占位或默认值），不报错；有事件数据时再覆盖为真实计算值。
- **语言**：仍仅中文；若原始字段为英文（如队名、事件类型），在展示前转为中文或保留英文由产品定。

## 九、实现说明（已完成）

- **事件加载**：`football_ai/data/events.py` 支持从本地 StatsBomb JSON 文件（事件数组）加载，并归一化为 `type, team, possession_team, duration, shot_xg` 等字段。
- **战术指标**：`football_ai/tactics/metrics.py` 从事件表计算控球率（按 duration 汇总）、xG（Shot 事件 shot_xg 求和）、射门次数（Shot 事件数）。
- **队名映射**：可选 CSV（`statsbomb_name, report_name`）经 CLI `--team-mapping` 或配置传入，将数据源英文队名映射为报告用中文。
- **示例数据**：`data/test/sample_statsbomb_events.json` 为最小示例，可用于本地跑通；替换为真实 StatsBomb 英超单场 JSON 即可得到真实指标。

**运行示例（赛后报告 + 事件数据）：**
```bash
python -m football_ai.cli post --home 巴萨 --away 阿拉维斯 --round 10 \
  --events data/test/sample_statsbomb_events.json \
  --team-mapping config/team_name_mapping.example.csv
```
