# 模型现状与可改进点

## 一、当前模型大致水平

| 模块 | 说明 | 表现/局限 |
|------|------|-----------|
| **Poisson（xG）** | 用赛前预期 xG + 联赛校准算胜负平/让球/比分 | 有可靠 xG 时合理；**缺 xG 时用 0.5/0.5 默认，接近 33/33/33，信息量低** |
| **ML（XGB）** | 五大联赛各一个 2024 训的 XGB，特征含 xG/状态/H2H/Elo 等 | 跨赛季回测（2024 训→2025 测）**胜负平命中约 46%～49%**（随机约 33%） |
| **融合** | Poisson 与 ML 概率加权（可配置权重） | 综合两种信息，比分/让球仍来自 Poisson |
| **盘口参考** | 赔率隐含概率按权重与模型概率融合 | 需赛程 CSV 有赔率；可选 **config/odds_team_mapping.csv**（API 队名→赛程队名）提高匹配率 |
| **价值方向** | 模型概率 − 赔率隐含 > 阈值时标 value | 仅作参考，不构成投注建议 |

**结论**：在「有历史数据、有校准、有 xG 或盘口」的前提下，模型能给出有信息量的概率和对比；**最大短板是输入质量**（xG 常缺、历史数据已标注不可靠）。ML 已支持由胜负平推算**让球**（主让 0.5/1/受让 1）及**最可能比分**（无 xG 时为 1-0/0-1/1-1 启发式；**有 xG 时用 Poisson 在胜负平对应类别内取最可能比分**）；`win_by_one_ratio` 可配置。批量预测 CSV 支持**最可能比分、次可能比分、第三可能比分**（Poisson/融合路径有详情时写入）。

## 二、已标注的欠缺（文档/代码内）

1. **历史数据质量**  
   README 明确写：**「当前目录内数据已确认与真实赛果严重不符，请勿直接用于校准/回测，须替换为权威来源或逐条核对后再用。」**  
   → 校准与回测结果目前不可信，需替换为权威赛果后再做。

2. **预期 xG 经常为空**  
   赛程 CSV 里 xG 多为空时，Poisson 用默认 0.5/0.5，输出接近 33/33/33。  
   → 需要：用 `data/expected_xg/` 或 `--expected-xg` 表、或 Understat 等拉取球队/场次 xG 并填进赛程或预测入口。

3. **盘口匹配依赖队名**  
   拉盘口时用主客队名字符串匹配 API 返回的赛事，队名不一致则匹配不到。  
   → **已做**：可选队名映射表 **config/odds_team_mapping.csv**（列 `api_name`, `our_name`），将 The Odds API 队名映射为赛程 CSV 所用队名，见 **config/odds_team_mapping.example.csv**。复制为 `odds_team_mapping.csv` 并按需增补即可提高匹配率。

4. **ML 让球与最可能比分**  
   **已实现**：由 ML 输出的胜负平概率推算让球结果（主让 0.5/1、主受让 1）；最可能比分：无 xG 时为 1-0/0-1/1-1 启发式，有 xG 时用 Poisson(λ_h, λ_a) 在 ML 胜负平对应类别内取概率最大的比分；`config/settings.yaml` 中 `predictions.win_by_one_ratio` 可配置「一球小胜」中让胜/让平比例。

5. **ML 未用赔率特征**  
   训练特征只有 xG、状态、H2H、Elo 等，**没有赔率或赔率隐含概率**。  
   → 若历史数据中能稳定提供每场赔率，可加「赔率隐含概率」等特征重新训 ML，再评估效果。

6. **校准文件未入库**  
   `config/calibration_*.yaml` 在 .gitignore，新环境需自己跑 `./run.sh calibrate` 才会按联赛应用校准。  
   → 文档/下一步指南已说明；若希望开箱即用，可保留示例校准或 CI 中生成。

7. **不确定性未量化**  
   输出只有点估计概率，没有置信区间或预测区间。  
   → 可选：对 Poisson 或 ML 做简单 bootstrap/贝叶斯或集成方差，给出区间。

## 三、可改进方向（按优先级）

| 优先级 | 方向 | 说明 |
|--------|------|------|
| 高 | **替换/核对历史数据** | 用权威赛果（官方、Opta、FBref 等）替换 `data/historical/`，再跑校准与回测，结果才可信。 |
| 高 | **补足预期 xG** | 用 Understat/FotMob 等拉取并写入 `data/expected_xg/` 或赛程 CSV；预测时传 `--expected-xg`，减少 0.5/0.5 默认。 |
| 中 | **盘口队名映射** | **已实现**：`config/odds_team_mapping.csv`（api_name → our_name），拉盘口时自动加载，提高 API 与赛程匹配率。 |
| 中 | **ML 加入赔率特征** | 历史数据有赔率时，特征加「主/平/客隐含概率」等，重新训练并回测。 |
| 低 | **概率区间** | 为 Poisson 或 ML 输出增加简单置信区间（如 90% 区间）。 |
| 低 | **亚洲盘/其他市场** | 若需亚洲盘或大小球，需对接对应市场与格式，并在输出中区分。 |

---

## 四、一句话总结

**模型结构（Poisson + ML + 融合 + 盘口参考）已经搭好，能跑通并有一定信息量；当前主要欠缺是「输入质量」和「历史数据可信度」——补上权威赛果和预期 xG、并做好队名/盘口对接后，再评估与迭代模型会更稳妥。**
