# 历史数据 · 定义与清洗规范

本文档明确历史场次数据的**语义定义**、**已知问题**与**清洗流程**。在将数据用于校准、回测、近期状态、Elo 或 ML 前，必须完成来源核对与必要清洗。

---

## 一、数据定义（目标状态）

### 1.1 场次唯一性与顺序

- **一条记录** = 一场已完赛的比赛，在该联赛该赛季内**唯一**（主客队 + 比赛日 或 主客队 + 比赛周 可唯一确定）。
- **时间顺序**：场次必须能按**真实比赛时间**排出唯一、连续的先后关系，用于：
  - 近期状态（「近 N 场」）
  - 历史交锋（按时间取最近若干场）
  - Elo 更新、xPts 累计、ML 特征（仅用「该场之前」的数据）

因此，**比赛日期**或**唯一且连续的比赛周编号**是核心索引，而非任意「轮次」标签。

### 1.2 字段语义（规范）

| 字段 | 类型 | 必选 | 语义与要求 |
|------|------|------|------------|
| **season** | 整数 | 是 | 赛季年（如 2024 表示 2024–25 赛季）。与数据源约定一致。 |
| **match_date** | 字符串 YYYY-MM-DD | **强烈推荐** | 比赛日。**作为时间排序与去重的首要依据**；无日期时退化为 round。 |
| **round** / **matchweek** | 整数 | 是* | 比赛周编号：在同一赛季内**连续、唯一**，且与官方赛程一致（如第 1 周、第 2 周…）。*在提供 match_date 且能由日期推导比赛周时，可弱化为可选。 |
| **home_team** | 字符串 | 是 | 主队名，与报告/映射一致。 |
| **away_team** | 字符串 | 是 | 客队名。 |
| **goals_home** | 整数 | 是 | 主队实际进球，**须与权威来源核对**。 |
| **goals_away** | 整数 | 是 | 客队实际进球。 |
| **xg_home** | 浮点数 | 是 | 主队预期进球（xG）。 |
| **xg_away** | 浮点数 | 是 | 客队预期进球（xG）。 |

- **当前实现**：CSV 中仍使用 `round` 作为必选；若存在 `match_date`，加载器会保留，供排序与校验使用。后续可增加「由 match_date 推导 matchweek」的脚本，再逐步用 matchweek 替代不规范的 round。

### 1.3 关于「轮次」的明确约定

- **禁止**：`round` 仅为随意编号、或与官方比赛周不一致、或存在断号/重号。
- **目标**：`round` 表示**该联赛该赛季内的正式比赛周**（如德甲第 1 轮…第 34 轮），且同一 round 内多场比赛共享同一「周」概念，顺序可由 match_date 细化。
- **若数据源无可靠轮次**：应优先使用 **match_date** 排序；round 可先填 0 或由脚本根据 date 反推后再写回。

## 二、已知问题（为何必须清洗）

**当前仓库内 historical 数据已确认与真实赛果严重不符**（含通过 Understat 拉取的 2024 五大联赛）。在未替换为权威来源或逐条核对比分前，不得用于校准、回测及报告中的任何衍生指标。

1. **轮次混乱**  
   「轮次」并非严格按照一个**连续、唯一**的比赛周来编号，存在：
   - 与官方赛程不一致
   - 断号、重号或非单调
   - 不同数据源混用导致同一赛季内 round 语义不一致  

   这类数据若直接用于「近 N 场」「第 R 轮前」等逻辑，会产生错误顺序与错误样本。

2. **比分错误**  
   部分场次的主客队比分与权威来源（联赛官网、ESPN、Transfermarkt 等）不一致，导致：
   - 积分、胜负、xPts、Elo 等衍生指标错误
   - 回测与校准结果不可信

3. **来源不明**  
   若未标明数据来自何处（如 Understat、FBref、某游戏、某模型输出），无法判断是抓取错误、模拟数据还是混源，清洗时难以定责与修正。

**结论**：在用于任何分析目的前，必须完成**来源核对**与**索引/比分清洗**。

---

## 三、清洗与核对流程（三步）

### 第一步：核对来源

- **明确记录**：每条数据（或每个文件/赛季）标注**数据来源**（如 Understat、FBref、ESPN、手工录入）及抓取/生成时间。
- **排除非真实数据**：若来自游戏（如足球经理）、预测模型输出或未知脚本，必须单独标注且不得与真实赛果混用；用于校准/回测的只能是**真实赛果**。
- **建议**：在仓库或 CSV 同目录增加 `sources.csv` 或 README 记录，例如：`EPL pl_2024.csv → Understat，抓取于 2024-08-01`。

### 第二步：建立正确索引

- **放弃或重命名不可靠的 round**：若当前 `round` 不符合「连续、唯一、与官方一致」的比赛周语义，应在文档与代码中将其视为「原始轮次（未校验）」，不再用于时间顺序逻辑。
- **引入 match_date**：  
  - 从权威赛程或数据源补全每场比赛的 **match_date**（YYYY-MM-DD）。  
  - 排序与「第 R 轮前」「近 N 场」等逻辑**优先按 match_date**；同一 match_date 内可按主客队或开球时间进一步排序。
- **生成或校验 matchweek**：  
  - 若有官方比赛周，以之为准写入 `round` 或新列 `matchweek`。  
  - 若无，可根据 match_date 按周聚合生成「比赛周」编号（例如同一自然周或同一「比赛周」窗口内的场次同属一周），再写回 CSV，并注明「由 match_date 推导」。

### 第三步：逐条核对比分

- **权威来源**：以联赛官网、ESPN、Transfermarkt、FBref 等为基准，对**关心的联赛/赛季**逐场核对 goals_home、goals_away。
- **修正与记录**：发现错误即修正 CSV，并建议在版本历史或 changelog 中简要记录（如「修正 2024-09-15 场次 A vs B 比分」）。
- **自动化辅助**：若有条件，可写脚本从单一权威源拉取赛果，与现有 CSV 逐场 diff，标出不一致再由人工确认后修正。

## 四、与本项目代码的衔接

- **加载**：`load_historical_matches` 会保留 CSV 中的 `match_date`（若存在）；其他可选列（如 ht_goals_*）也会保留。
- **排序**：所有依赖「时间顺序」的模块（近期状态、H2H、Elo、xPts、ML 特征）应**优先按 match_date 排序**，无 match_date 时再按 (season, round)。具体在调用侧或加载后统一做一次 `sort(key=(match_date or (season, round)))`。
- **校验脚本**：`scripts/validate_historical_data.py` 提供：（1）默认扫描无效场次；（2）`--merged-2024` 对合并的 2024 数据做场次数量、重复、轮次范围、比分/xG 范围检查，可选 `--ref <参考CSV>` 与权威样本逐场 diff。详见 [2024 合并数据核对流程](历史数据-2024合并数据核对流程.md) 及 [data/historical/README.md](../data/historical/README.md)。

## 五、总结

| 项目 | 要求 |
|------|------|
| 时间顺序 | 以 **match_date** 为首要依据；round 仅当为「连续、唯一比赛周」时才可信。 |
| 比分 | 必须与**权威来源**逐条核对后再用于分析与回测。 |
| 来源 | 每条数据或每文件标明来源，排除游戏/模型等非真实赛果。 |
| 清洗顺序 | 先来源 → 再索引（match_date + matchweek）→ 再比分。 |

在完成上述三步前，现有历史数据应视为**未校验**，仅可用于探索性分析；**校准、回测及生产用报告**应在清洗与核对后再使用。
