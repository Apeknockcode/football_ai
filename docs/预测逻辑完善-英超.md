# 预测逻辑完善：面向英超的准确预测

当前预测基于**单场 xG + Poisson 模型**，未利用历史英超数据做校准与校验。要提升英超比赛的预测准确度，需从数据、模型、校验三方面完善。

---

## 一、当前逻辑的局限

| 现状 | 局限 |
|------|------|
| 只用本场 xG | 未考虑联赛整体分布（如英超平局率、主客场差异） |
| Poisson 独立假设 | 主客队进球完全独立，未做历史校准 |
| 无历史结果 | 无法验证「xG → 胜负平/比分」在英超上的表现 |
| 无主客场/实力 | 未显式加入主队优势、球队实力等 |

---

## 二、完善方向（按优先级）

### 1. 积累「英超历史场次」数据（必备）

**目的**：用真实结果校准和校验模型，而不是拍脑袋参数。

**需要的数据**（每场一行或一文件）：

- **事件/结果**：主客队、轮次、**主队 xG、客队 xG**、**实际比分**、**半场比分**（若有）。
- **赛程**：比赛日期、开球时间（可从现有 fixtures 扩展）。
- **规模**：至少 **一个完整赛季（38 轮 × 多场）**，越多越好；能跨多赛季更好。

**来源建议**：

- StatsBomb 开放数据中若有英超，可直接用。
- 若无，需通过商业/教育授权拿到英超 2022/23、2023/24、2024/25 等赛季的 **events + 赛果**。
- 先保证：**每场有 (xG_home, xG_away, 主队进球, 客队进球, 半场主队进球, 半场客队进球)**，再谈后续模型。

**落地**：在项目里建「历史数据」目录（如 `data/historical/`），统一格式（CSV 或 Parquet），字段包含：`season, round, home_team, away_team, xg_home, xg_away, goals_home, goals_away, (ht_goals_home, ht_goals_away)`。

---

### 2. 用历史数据做「参数校准」

**目的**：让 Poisson（或后续模型）的参数符合英超实际，而不是默认假设。

可做的校准（有历史表后即可做）：

- **平局率**：在英超历史里算「平局占比」；若明显偏离 25%，可在模型里用该比例替代固定 25%。
- **主客场**：在历史数据里算「主队 xG 与客队 xG 对胜负的影响」；若存在明显主队优势，可对主队 xG 做小幅放大（或对客队缩小），再进 Poisson。
- **xG → 实际进球**：用历史场次做「xG 对实际进球」的回归或分桶，得到修正系数（例如英超是否普遍「xG 略高估/低估」），在预测前对 xG 做一次缩放。

**实现思路**：写一个「校准脚本」：读入 `data/historical/*.csv`，计算上述统计量，输出一份 **校准参数文件**（如 `config/calibration_pl.yaml`：平局率、主队系数、xG 缩放等）。预测服务在算概率前先读该校准文件，再代入 Poisson（或下一阶段的模型）。

---

### 3. 升级「胜负平 / 比分 / 半全场」模型（可选但推荐）

**目的**：从「单场 Poisson」升级为「用历史英超结果训练/拟合」的模型，提升准确度。

- **胜负平**  
  - 方案 A：仍用 Poisson(xG)，但 xG 先经校准（主客系数、xG 缩放），再算 P(主胜/平/客胜)。  
  - 方案 B：用历史 (xG_h, xG_a, 主队进球, 客队进球) 拟合一个简单模型（如有序 Logit、或分桶概率表），输入本场 xG 输出 P(主胜/平/客胜)。  

- **比分**  
  - 继续用 Poisson 时，用校准后的 xG 生成 P(i-j)；  
  - 若有半场 xG，可用「半场 Poisson + 全场 Poisson」改进半全场与比分一致性。

- **半全场**  
  - 若有**半场比分**历史数据：可统计「(半场结果, 全场结果)」的联合分布，用本场预测的「全场胜负平」反推或约束半全场概率。  
  - 若无半场数据：保持「半场与全场独立 + 同一胜负平分布」的简化假设，但用历史全场胜负平概率做校准。

**实现思路**：在 `football_ai/predictions/` 下增加「校准模块」与「历史驱动模型」可选路径；当存在 `config/calibration_pl.yaml` 和 `data/historical/` 时，优先用校准/历史模型，否则退回当前 Poisson。

---

### 4. 主队 / 客队标识与赛程一致

**目的**：确保「主客」与赛程、事件数据一致，避免主客颠倒导致预测反了。

- 事件数据里若有「主客」标记，加载时统一：主队 = home，客队 = away。  
- 赛程表与报告中的主客队名、轮次，与历史数据里的命名一致（可用同一份 `team_name_mapping`）。  
- 校准时的「主队优势」等，一律按「主队 = 主队 xG / 主队进球」定义。

---

### 5. 回测与准确率指标

**目的**：用历史英超场次做回测，看「预测概率」与「实际结果」是否一致，并据此调参或换模型。

**做法**：

- 对每场历史比赛：用该场 xG（及可选半场 xG）按当前（或校准后）模型得到 P(主胜)、P(平)、P(客胜)。  
- 计算：  
  - **Brier 分数**：对胜负平三类概率与 0/1 结果的均方误差，越小越好。  
  - **对数似然**：每场取「实际结果」对应的预测概率的对数再求和，越大越好。  
  - **比分**：可看「最可能比分」的命中率，或「前 3 个最可能比分」的覆盖率。  

**落地**：写一个「回测脚本」：读历史表，逐场调用现有预测接口，汇总 Brier、对数似然、命中率；输出报告或写入 `docs/backtest_pl_YYYYMM.md`。每次改校准或模型后重跑回测，确保「未来遇到英超比赛」前有数字依据。

---

## 三、建议实施顺序

1. **先有数据**：拿到至少一季英超的「事件 → xG + 赛果（及半场比分若可能）」并落表。  
2. **再做校准**：用该季数据算平局率、主客系数、xG 缩放，写出 `calibration_pl.yaml` 并接入预测服务。  
3. **回测**：在同一季上回测当前 Poisson+校准，看 Brier/对数似然是否改善。  
4. **再升级模型**：若回测仍不理想，再考虑历史驱动的胜负平/比分/半全场模型（拟合或查表）。  
5. **持续迭代**：新赛季数据进来后，重新校准、回测，再决定是否更新模型或参数。

## 四、已实现（先数据 → 再校准 → 再回测 → 再升级模型）

- **数据**：`data/historical/README.md` 约定 CSV 格式；`data/historical/_common/sample_pl.csv` 示例；`football_ai.data.historical.load_historical_matches()` 加载。
- **校准**：`scripts/calibrate_pl.py` 从历史 CSV 算 `draw_rate`、`home_xg_factor`、`xg_scale`，写入 `config/calibration_pl.yaml`。
- **回测**：`scripts/backtest_pl.py` 逐场用当前（或校准后）模型预测，输出 Brier、平均对数似然；可选 `--calibration`。
- **预测接入校准**：存在 `config/calibration_pl.yaml` 时，`football_ai.predictions.service` 自动对 xG 做主队系数与 xG 缩放后再算概率。
- **升级模型**：待回测不理想时再扩展（历史拟合/查表等）。

### 如何解读这些结果（通俗版）

跑完**校准**和**回测**后，终端会打出几行数字，可以这样理解：

**1. 校准结果（calibrate_pl.py 的输出）**

- **draw_rate（平局率）**：历史数据里「平局」占多少比例。例如 25% 表示每 4 场大约 1 场平局。用来了解联赛风格，后续可用来微调模型。
- **home_xg_factor（主队 xG 乘数）**：从历史看，主队「实际进球 / xG」相对客队是否更高。>1 表示主队有主场优势，预测时会把主队 xG 稍微放大。
- **xg_scale（xG 缩放）**：历史总实际进球 ÷ 历史总 xG。若 <1 表示整体上 xG 略高估了进球，预测时会把 xG 整体缩小一点。

这些只是**从你提供的历史表里算出来的统计量**，样本少（比如只有 4 场）时数字会很不稳，只能当参考。

**2. 回测结果（backtest_pl.py 的输出）**

- **场次**：用来回测的比赛数量（和你的历史 CSV 行数一致）。
- **Brier（越小越好）**：预测概率和真实结果差多少。  
  - 完美预测 = 0；越接近 0 越好。  
  - 随机猜（主胜/平/客胜各 1/3）大约在 0.65 左右。  
  - 例如 0.32 表示比随机猜好不少，但还有改进空间。
- **平均对数似然（越大越好）**：每场「实际结果」对应的预测概率取对数再平均。  
  - 越接近 0 越好（表示预测到真实结果的概率高）；负数表示概率小于 1，例如 -0.61 表示平均每场预测到真实结果的概率大约在 e^{-0.61} ≈ 0.54。

**3. 当前为什么只有 4 场？**

因为示例数据 `data/historical/_common/sample_pl.csv` 只放了 4 场。**4 场太少**，校准和回测的数字都**不能当真**，只能说明「流程跑通了」。  
等你把**至少一季英超**（几十到几百场）按同样格式放进 `data/historical/`，再跑一次校准和回测，得到的 Brier、对数似然才有参考价值，才能用来判断要不要调参数或升级模型。

**4. 一句话总结**

- **校准**：从历史表里算出「平局率、主队优势、xG 缩放」三个数，让预测更贴近该联赛。  
- **回测**：用这些参数在历史场上算一遍预测，看 Brier 和对数似然——数字越好，说明模型越靠谱；样本太少时先别下结论。

## 五、双轨：Poisson 与 ML（XGBoost/LightGBM）

- **Poisson（默认）**：基于赛前预期 xG + 联赛校准，输出胜负平/让球/比分/半全场；适用于有 xG 无历史或快速预测。
- **ML 轨**：用历史场次训练 XGBoost/LightGBM（`scripts/train_ml.py --model xgb` 或 `lgb`），保存 pkl；`predict_batch --model ml` 需同时提供 `--ml-model`、`--historical`、`--season`，用该场之前的历史构建特征并输出胜负平概率。让球/比分在 ML 轨下为占位。
- **回测**：`backtest_pl --model poisson` 与 `--model ml --ml-model <pkl>` 可对同一批历史场次比较 Brier、胜负平命中率；ML 轨不输出比分命中。回测结果用于评估**长期统计表现**，不保证未来单场结果。

### 融合预测（ensemble）

- **做法**：`predict_batch --model ensemble` 同时跑 Poisson 与 ML，对**胜负平概率**做加权平均后归一化；**比分、让球**仍用 Poisson 输出。
- **公式**：`P_final = (1 - w) * P_poisson + w * P_ml`，权重 `w` 在 `config/settings.yaml` 的 `predictions.ensemble_ml_weight`（默认 0.5）。
- **效果**：Poisson 依赖 xG 与联赛校准，ML 利用近期、赛季、H2H、Elo 等；融合可减轻单一模型偏差，往往比单用其一更稳。建议用 backtest 在同一历史集上对比 poisson / ml / ensemble 的 Brier 后再定权重。

## 六、如何理解模型：长期 vs 单场

- **长期**：模型与回测的目标是在**大量场次**上保持统计优势（如更低的 Brier、更好的校准），而不是「猜对每一场」。
- **单场**：任意一场比赛的结果都会受到红牌、失误、偶然进球、裁判尺度等不可预测因素影响，因此单场命中率无法保证，也不应作为评价模型的唯一标准。
- **正确用法**：用 backtest 输出（Brier、校准曲线、胜负平命中率）评估模型在历史数据上的表现；新赛程上做预测时，将结果视为「概率参考」而非「单场必中」。

## 七、黑天鹅与合规

- **黑天鹅**：极端结果（大冷门、绝杀、争议判罚等）在足球中客观存在；模型不试图预测此类事件，仅基于 xG、历史、赔率隐含等做概率估计。
- **合规**：所有预测与价值方向输出均**仅供参考、不构成投注建议**；用户需遵守当地法规。价值方向（模型概率高于赔率隐含超过设定阈值）仅作信息展示，不推荐具体投注行为。

## 八、小结

- **准确预测英超**的前提是：有**英超历史场次**的 xG 与结果数据。  
- **完善分析逻辑**的路径是：**历史数据 → 校准参数 → 回测验证 → 必要时升级模型**。  
- 当前代码结构（单场 xG → Poisson → 胜负平/让球/比分/半全场）可保留；在此基础上增加「校准层」「历史数据管道」与可选「ML 轨」，即可在不推倒重来的前提下，让未来遇到的英超比赛预测更准确、可验证。
- 理解「长期 vs 单场」与「黑天鹅与合规」见上文第六、七节。
